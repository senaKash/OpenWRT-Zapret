# OpenWRTZapret — единый пакет (экспериментальный прототип)

Цель: **один APK приложения** с `nfqws2`, необходимыми файлами zapret2, LuCI и backend OpenWRTZapret.
Системные зависимости (`luci-base`, nftables, kmod и библиотеки) остаются пакетами OpenWrt. Их нельзя безопасно упаковать в один архитектурно-независимый APK.

## Статус

**Экспериментальная отдельная сборка.** Makefile подготовлен, но сборка с OpenWrt SDK/buildroot и установка на роутер ещё НЕ проверены. Не устанавливать на рабочий r31.

- Стабильные `zapret2` и `luci-app-zapret2` остаются без изменений.
- Единый пакет называется `openwrtzapret` и конфликтует с обоими пакетами: общие файлы `/opt/zapret2`, `/etc/init.d/zapret2`, LuCI и RPC нельзя одновременно отдавать двум пакетам.
- Миграция старой установки **не реализована**: пакет откажется устанавливаться поверх неё. Не используйте `--force`, не удаляйте рабочие пакеты без резервной копии.
- Пути файлов zapret2 не менялись, чтобы сохранить совместимость backend со стратегиями и списками.

## Очистка (первый проход)

Исключены `blockcheck2.sh` и `blockcheck2.d`, не используемые страницами OpenWRTZapret.
Временно сохранены `ip2net`, `mdig`, `common`, Lua и fake-файлы: они могут использоваться штатными скриптами, конфигурацией и импортированными стратегиями. Удалять их можно только после проверки вызовов в исходниках zapret2 и реальной сборке.

## Сборка для одной архитектуры

Из корня подготовленного OpenWrt buildroot или SDK добавьте локальный feed:

```text
src-link openwrtzapret /путь/к/OpenWRT-Zapret
```

Далее выполните (если feed уже настроен — шаг регистрации не нужен):

```sh
./scripts/feeds update -a
./scripts/feeds install -p openwrtzapret -f openwrtzapret
make defconfig
make package/feeds/openwrtzapret/openwrtzapret/compile V=s
```

Или выполните `tools/build-unified.sh` при уже подготовленном feed и настроенной сборке. Выходной APK будет `openwrtzapret-0.9.20260307-r1.apk` в каталоге `bin/packages/<pkg_arch>/openwrtzapret/`.

## Архитектуры

Универсальность **исходников и процесса сборки**, но **не одного физического APK**: каждый целевой SDK собирает `nfqws2` под свою архитектуру. Упаковка LuCI в тот же APK делает его архитектурно-зависимым. Для OpenWrt SNAPSHOT важна также совместимость модулей ядра и настроек SDK.

Для автоматической публикации понадобится отдельная матрица SDK/прошивок и реальная проверка сборки на каждом target/subtarget. В текущем прототипе такой матрицы ещё нет.

## До выпуска релиза

1. Собрать пакет в OpenWrt SDK для одной архитектуры и проверить состав/размер с помощью `apk` и перечня файлов.
2. Проверить чистую установку на тестовом роутере/образе: сервис RUNNING, nftables/NFQUEUE, LuCI, стратегии, тесты, списки, импорт и перезапуск.
3. Реализовать миграцию r31 (резервные копии профилей/списков, удаление двух старых пакетов и откат при сбое).
4. После этого добавить сборки других архитектур и GitHub Releases.

Не используйте текущий `owz-build` для единого APK: он специально обновляет и устанавливает стабильный `luci-app-zapret2`.
